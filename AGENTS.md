# Работа над Эйрвелем

Перед изменениями прочитайте README.md, ROADMAP.md, PROJECT_STATE.md и docs/SPECIFICATION.ru.md. Работа ведётся по исходному ТЗ. Текущая версия — ранний этап, не полноценная игра.

- Пользователь — будущий игрок. Не раскрывайте секреты, повороты, решения загадок и концовки в ответах, именах веток, коммитах и PR. Сюжетные материалы храните в data/narrative и не цитируйте в отчётах. Не спрашивайте пользователя о содержании сюжета.
- Используйте существующий checkout. Облачная задача уже изолирована; не создавайте worktree без прямого запроса.
- Godot 4.6.3 standard, GDScript, compatibility renderer. На облачной машине: source /workspace/.godot-env/env.sh.
- Игрок начинает человеком. Сверхъестественный путь только через добровольное сюжетное решение; не добавляйте его в создание персонажа.
- Пользовательские тексты — в data/localization/strings.csv, ключи стабильны; используйте tr(). Не добавляйте абсолютные пути в игру. Сохранения только user://.
- Новую логику проверяйте существующими или содержательными новыми тестами. До отправки: импорт, bash tools/test.sh, git diff --check и экспорт при изменении ресурсов/настроек сборки.
- Проверяйте код возврата и отсутствие SCRIPT ERROR. Нулевой код одного импорта не доказывает исправность игры.
- Не меняйте облачный черновик и не публикуйте среду в рамках разработки игры без запроса. Публикация среды и push проекта — разные операции.
- Используйте ветки и PR. До push подтвердите приватность существующего remote. Не создавайте публичных репозиториев, не выводите секреты, не обходите облачный прокси. Не используйте force-push.
- Обновляйте PROJECT_STATE.md: что проверено, какие ограничения есть и следующий конкретный шаг. Не обещайте работу после окончания активной задачи; сохранённые файлы не означают фоновую разработку.
- Полную цель ТЗ не сокращать до демо: поэтапно развивать игру, явно отделяя выполненное от запланированного. Не заявлять продолжительность, баланс и FPS без измерений на целевом Mac.
